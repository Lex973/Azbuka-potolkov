## 1. Задача и рамки

- Формы:
  - «Обсудить проект» (`ContactDialogButton`): шапка, мобильное меню, hero, страницы проектов и видов потолков.
  - «Записаться в студию» (`StudioVisitDialogButton`): финальная секция главной.
- Каждая заявка становится одним сообщением в Telegram: в личном чате Романа с ботом (или в закрытой группе, если получателей станет несколько).
- Бот только пишет в чат: команд не принимает, webhook и polling не нужны.
- Базы данных и CRM нет (`DEVELOPMENT_RULES.md`, раздел 10). Сайт не хранит заявки. Если доставка не удалась, посетитель видит ошибку, а его данные остаются в полях: можно повторить или позвонить.

## 2. Схема

```text
Браузер                          Сервер сайта (Docker, next start)              Telegram
───────                          ─────────────────────────────────              ────────
форма (noValidate)
  │ parseLead — те же правила, что на сервере
  │ requestId = randomUUID() на одно заполнение
  ▼
submitLead(FormData) ──POST /api/leads──► createLeadHandler
  таймаут 20 с                      1. Origin в списке разрешённых            ─► 403
                                    2. Content-Type multipart                 ─► 415
                                    3. лимит по IP (все попытки)              ─► 429
                                    4. тело потоком, ≤ 16 КБ                  ─► 413
                                    5. honeypot → тихий «успех», запись в лог ─► 200
                                    6. parseLead (граница доверия)            ─► 400
                                    7. конфигурация задана                    ─► 503
                                    8. дедупликация по requestId:
                                       уже доставлено → 200 без отправки
                                       9. общий лимит (только отправки)       ─► 429
                                       10. sendTelegramMessage ──HTTPS──► Bot API
                                           дедлайн 12 с; relay — одна попытка
                                           (в режиме relay — через Cloudflare Worker,
                                            см. раздел 6)
  ◄── JSON { status } ──────────── 200 | 502
```

### Почему Route Handler, а не Server Action

- **Server Action ломается на деплое.** Её ID меняется при каждой сборке и ротируется не реже раза в 14 дней (`node_modules/next/dist/docs/01-app/02-guides/server-actions.md`, «Deployment considerations»). Сайт — один контейнер, деплой его пересоздаёт. Вкладка, открытая до деплоя, получит «Failed to find Server Action», и заявка будет потеряна. `deploymentId` спасает только при навигации, а не при отправке из открытого окна.
- **Route Handler стабилен.** У `POST /api/leads` постоянный адрес, его легко тестировать. `DEVELOPMENT_RULES.md` требует отправлять «через `FormData` и небольшой изолированный адаптер».
- **Цена выбора.** Встроенная проверка Origin из Server Action теряется, её пришлось сделать вручную (раздел 5). Рассинхрон версий переезжает в контракт API: старый JS после деплоя шлёт старые поля. **Правило: контракт `/api/leads` меняется только обратно совместимо.** Новые поля необязательны или имеют значение по умолчанию.

## 4. Данные

### Поля

Длины считаются так же, как HTML `maxLength`, в единицах UTF-16 (`string.length`), после нормализации.

| Поле            | Правило                                                                                                                                                                                 |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kind`          | `project` или `studio`, ставит хук                                                                                                                                                      |
| `requestId`     | UUID, ставит хук: один на заполнение, после успеха новый                                                                                                                                |
| `name`          | обязательно; NFC, удаляются символы `\p{Cc}` и `\p{Cf}`, пробелы схлопываются; 2–80 символов                                                                                            |
| `phone`         | обязательно; только цифры, пробелы, `()-` и `+` в начале, до 20 символов. Российский номер (`8…`/`7…` из 11 цифр, `9…` из 10) приводится к `+7XXXXXXXXXX`; иначе нужен `+` и 10–15 цифр |
| `message`       | только для проекта, необязательно; до 1000 символов; переводы строк сохраняются, больше двух подряд схлопываются                                                                        |
| `preferredTime` | только для студии, необязательно; одна строка до 120 символов                                                                                                                           |
| `page`          | путь страницы; `^/[a-z0-9/-]*$`, не `//`, до 200 символов; иначе отбрасывается без ошибки                                                                                               |
| `leadTrap`      | honeypot, должно быть пустым; имя выбрано так, чтобы его не автозаполняли браузеры                                                                                                      |

- Значения-файлы (`File`) считаются пустыми.
- Для повторяющихся имён берётся первое значение.
- Поля, которые не относятся к виду заявки, игнорируются.
- В HTML остаются `required`, `minLength`, `maxLength`, `inputMode`, `autoComplete`, а форма работает с `noValidate`: ошибки показывает `parseLead`. Атрибут `pattern` убран, чтобы правила не расходились с `lead.ts`.

### Сообщение

Простой текст **без `parse_mode`**, превью ссылок отключено.

```text
Заявка: обсудить проект · #3F9A1C
Имя: Анна
Телефон: +7 999 000-00-00
О проекте: Квартира 120 м², черновая отделка
Страница: https://azbukapotolkov.ru/projects/skyline-apartment
```

- Скрытые ссылки (`text_link`) и форматирование невозможны.
- Обычные URL, `@упоминания` и телефоны Telegram всё равно сделает кликабельными. Клиент может вставить ссылку, и это нужно понимать сотрудникам. Риск низкий, отдельно не обрабатывается.
- `#3F9A1C` — короткий ID заявки, первые 6 символов `requestId`. Он же пишется в лог. По нему видно дубль, если сервер его не распознал: первая попытка ушла в таймаут, но дошла.

### Контракт `POST /api/leads`

Запрос `multipart/form-data`. Все ответы — JSON с `Cache-Control: no-store`. Клиент смотрит на `status` в теле, а не на код: 502 может отдать и Caddy.

| Код | `status`                       | Когда                                                               |
| --- | ------------------------------ | ------------------------------------------------------------------- |
| 200 | `ok`                           | доставлено; повтор уже доставленного `requestId`; сработал honeypot |
| 400 | `invalid` + `errors`           | данные не прошли `parseLead` или тело не разобралось                |
| 403 | `forbidden`                    | `Origin` отсутствует или не в списке                                |
| 413 | `too_large`                    | заявленный или фактический размер тела больше 16 КБ                 |
| 415 | `unsupported`                  | не `multipart/form-data`                                            |
| 429 | `rate_limited` + `Retry-After` | лимит по IP или общий                                               |
| 502 | `delivery_failed`              | Telegram не принял сообщение, не ответил или ответил не-JSON        |
| 503 | `unavailable`                  | не заданы переменные окружения                                      |

`GET` и другие методы → 405 (Next).

## 5. Безопасность и надёжность

| Риск                    | Мера                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Утечка токена           | Токен только в env сервера, без `NEXT_PUBLIC_`. Модули сервера импортируют `server-only`. Токен не попадает в логи и ответы: ошибки `fetch` логируются кодом, без объекта и URL. При утечке — `/revoke` в @BotFather.                                                                                                                                                                                                                                                                                                                                                                                             |
| Дубли                   | Ключ дедупликации — хеш всей заявки вместе с `requestId`: доставленная заявка помнится 15 минут, параллельный запрос ждёт первый. Исправленная после ошибки заявка (тот же `requestId`, другие данные) уходит заново, менеджер узнаёт её по тому же `#ID`. Дедлайн сервера 12 с меньше клиентского таймаута 20 с, поэтому клиент не сдаётся, пока сервер ещё пытается. Запрос к Telegram не привязан к `request.signal`: закрытая вкладка не отменяет доставку.                                                                                                                                                   |
| Повторы                 | В режиме relay — одна HTTP-попытка на запрос формы, без автоматических повторов на 429 и ошибки соединения: новый Worker при малом остатке дедлайна мог продолжать доставку после ошибки сайта и создавать дубль при ручном повторе. В direct — один повтор на 429 с `retry_after` ≤ 5 с, если укладывается в дедлайн, либо на ошибку до соединения (`ECONNREFUSED`, `ENOTFOUND`, `EAI_AGAIN`, `UND_ERR_CONNECT_TIMEOUT`). На таймаут и 5xx автоматического повтора нет.                                                                                                                                          |
| Спам                    | Honeypot `leadTrap` с тихим успехом. Каждое срабатывание пишется в лог без ПДн, чтобы заметить ложные срабатывания. CAPTCHA (например, Yandex SmartCaptcha) — резерв на случай реальной атаки.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Флуд и блокировка формы | По IP: 10 попыток за 10 минут, считаются все. Общий лимит: 20 отправок в минуту (лимит Telegram для группы), считаются только реальные отправки, а не honeypot, невалидные и повторы. Таблицы в памяти чистятся и ограничены 10 000 ключей.                                                                                                                                                                                                                                                                                                                                                                       |
| Подмена IP              | Ключ — **последнее** значение `X-Forwarded-For`, его добавил ближайший прокси (Caddy). IPv6 берётся по /64. Условия надёжности: контейнер опубликован только на `127.0.0.1:3001` (иначе к нему можно обратиться в обход Caddy и подставить любой XFF), а в Caddy нет `trusted_proxies` и `header_up X-Forwarded-For`; это нужно подтвердить у владельца сервера. Если Caddy не передаст XFF, Next подставит адрес сокета — в rootless Docker это адрес шлюза, общий для всех посетителей. Поэтому при ключе из частной сети в лог один раз пишется `lead_client_ip_private`: после деплоя проверить, что его нет. |
| Чужие сайты и скрипты   | Обязательный `Origin` из списка: `siteConfig.url`, плюс `LEAD_ALLOWED_ORIGINS` (через запятую), плюс `http://localhost:*` и `http://127.0.0.1:*` при `NODE_ENV=development`. Сравнение по `new URL(origin).origin`. От curl это не защищает, от него защищают лимиты.                                                                                                                                                                                                                                                                                                                                             |
| Большое тело            | Заявленный `Content-Length` > 16 КБ — сразу 413. Тело читается потоком и обрывается на 16 КБ, так что chunked и HTTP/2 без длины тоже работают. Отдельно у владельца Caddy можно попросить `request_body { max_size 32KB }`.                                                                                                                                                                                                                                                                                                                                                                                      |
| Внедрение в текст       | Нет `parse_mode`. Удаляются `\p{Cc}`/`\p{Cf}`, в том числе RTL-override и zero-width символы.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ПДн в логах             | Пишутся только короткий ID, вид, результат и код Telegram. Имени, телефона и текста в логах нет.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Тихий отказ доставки    | Бота удалили из чата (403), группа стала супергруппой (400 + `migrate_to_chat_id`, пишется в лог), токен отозван (401), сеть недоступна. Тогда каждая заявка получает 502 с запасными контактами, но **компания об этом не узнает: мониторинга нет**. Принятый риск. Меры: тестовая заявка после каждого деплоя и смены настроек, запасной канал (почта) в `LEAD_BOT_OPTIONS.md`.                                                                                                                                                                                                                                 |
| Бот в чужих чатах       | После добавления в рабочий чат выключить «Allow Groups» в @BotFather (`/setjoingroups`). Бот пишет только в `TELEGRAM_CHAT_ID`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

## 6. Окружение и запуск

| Переменная              | Обязательно | Назначение                                                                                                                                                                 |
| ----------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TELEGRAM_RELAY_URL`    | для relay   | адрес ретранслятора, например `https://azbuka-leads-relay.<поддомен>.workers.dev`; только `https` (http — лишь для `localhost`). Если задан, токен и чат на сайте не нужны |
| `TELEGRAM_RELAY_SECRET` | для relay   | общий секрет с ретранслятором (его `RELAY_SECRET`), передаётся в заголовке `Authorization: Bearer`                                                                         |
| `TELEGRAM_BOT_TOKEN`    | для direct  | токен от @BotFather                                                                                                                                                        |
| `TELEGRAM_CHAT_ID`      | для direct  | ID чата: личный чат — положительное число, группа — `-100…`                                                                                                                |
| `TELEGRAM_API_BASE_URL` | нет         | адрес Bot API, по умолчанию `https://api.telegram.org`; в разработке — локальная заглушка                                                                                  |
| `LEAD_ALLOWED_ORIGINS`  | нет         | дополнительные разрешённые Origin через запятую                                                                                                                            |

Режим выбирается по `TELEGRAM_RELAY_URL`: задан — `relay`, иначе `direct`. В проде — `relay`.

- Переменные читаются при каждом запросе, пересборка не нужна. Но `docker restart` не перечитывает `--env-file`, поэтому после смены нужно пересоздать контейнер (`docker rm` + `docker run`).
- Файл с переменными на сервере держать с правами `600` и вне контекста сборки образа (`.dockerignore` → `.env*`), иначе токен попадёт в слой образа.
- `Dockerfile` и `deploy.sh` лежат только на сервере.
- `docker stop -t 20`: даёт идущим отправкам завершиться при деплое.

### Как создать бота и чат

Сейчас заявки получает один человек (Роман), поэтому группа не нужна:

1. В @BotFather: `/newbot`, получить токен.
2. Роман находит бота и нажимает **Start**: без этого бот не может ему писать (403).
3. ID чата — ID Романа в Telegram (положительное число): из `getUpdates` (`chat.id` в `message`) или от @userinfobot.
4. В @BotFather: `/setjoingroups` → Disable.

Если получателей станет несколько — закрытая группа:

1. В @BotFather: `/newbot`, получить токен.
2. Создать закрытую группу «Заявки с сайта», добавить бота и сотрудников.
3. Узнать ID группы: сразу после добавления бота написать в группу `/start@имя_бота` (обычные сообщения бот в режиме приватности не видит), затем запросить `getUpdates` (`curl https://api.telegram.org/bot<токен>/getUpdates` с компьютера, где Telegram доступен; не в браузере — токен останется в истории) и взять `chat.id` (из `message` или `my_chat_member`).
4. В @BotFather: `/setjoingroups` → Disable.
5. Задать переменные на сервере, пересоздать контейнер, отправить тестовую заявку с сайта.

### Telegram недоступен с сервера: ретранслятор на Cloudflare

`TELEGRAM_API_BASE_URL` **нельзя** направлять на прозрачный HTTP-прокси вида `/bot<token>/…`. Токен в URL попадёт в access-логи прокси, а сам прокси даст полный доступ к боту. Поэтому используется свой ретранслятор `telegram-relay/` (Cloudflare Workers, бесплатный тариф). Остальные варианты — в `LEAD_BOT_OPTIONS.md`.

```text
сайт ──POST https://…workers.dev/  {"text": "…"}──► Worker ──sendMessage──► Bot API
       Authorization: Bearer <секрет>               токен и chat_id — секреты Worker
```

Как устроен:

- Принимает только `POST /`, тело JSON `{ "text": string }` до 4096 символов, тело до 16 КБ. Другие поля, в том числе `chat_id`, игнорируются: писать можно только в свой чат.
- Секрет сравнивается без утечки по времени (через SHA-256). Тело читается только после проверки секрета.
- Ответ Bot API возвращается как есть, поэтому сайт разбирает 429, 403, `migrate_to_chat_id` тем же кодом. Свои ошибки Worker отдаёт в той же форме с `description: "relay: …"`: 401 — неверный секрет, 400/413 — тело, 500 — не заданы секреты, 502 — Telegram недоступен, 504 — Telegram не ответил за 10 с. В логах сайта виден только код: различить «relay: 401» и отозванный токен можно по логам Worker в панели Cloudflare.
- Ни Worker, ни сайт в режиме relay не делают автоматических повторов. При неудаче посетитель получает ошибку и может повторить вручную; в режиме direct остаётся ограниченный безопасный автоматический повтор.
- В логах Worker только статус, без текста заявок.
- Утечка секрета даёт только возможность писать в рабочий чат; токен бота на VPS сайта не хранится. При утечке — сменить `RELAY_SECRET` и `TELEGRAM_RELAY_SECRET`.

Развёртывание (из папки `telegram-relay/`, Wrangler не входит в зависимости сайта):

1. `npx wrangler@4.156.0 login` — один раз, вход в аккаунт Cloudflare в браузере.
2. Секреты Worker, каждый вводится в ответ на запрос и в репозиторий не попадает:
   - `npx wrangler@4.156.0 secret put TELEGRAM_BOT_TOKEN`
   - `npx wrangler@4.156.0 secret put TELEGRAM_CHAT_ID`
   - `npx wrangler@4.156.0 secret put RELAY_SECRET` — случайная строка не короче 32 символов, например из `node -e "console.log(crypto.randomBytes(32).toString('base64url'))"`.
3. `npx wrangler@4.156.0 deploy`, взять адрес `https://azbuka-leads-relay.<поддомен>.workers.dev`. Без секретов из шага 2 деплой откажется (`secrets.required`).
4. Проверить с VPS сайта: `curl -sS -X POST <адрес> -d '{}'` → `401 relay: unauthorized`. Это значит, что Worker доступен.
5. На сервере сайта задать `TELEGRAM_RELAY_URL` и `TELEGRAM_RELAY_SECRET`, пересоздать контейнер, отправить тестовую заявку с сайта.

Локальная проверка: `npx wrangler@4.156.0 dev` с секретами в `telegram-relay/.dev.vars` (в `.gitignore`). Тесты Worker идут вместе с остальными: `npm test`.

Заявки не сохраняются в очереди: при недоступности канала показывается ошибка, автоматической отложенной доставки нет.

## 7. Правовые вопросы (решает владелец сайта, лучше с юристом)

- **Трансграничная передача.** Имя и телефон — персональные данные. Передача на серверы Telegram, по распространённой позиции, — трансграничная передача, о ней нужно заранее уведомить РКН. Ретранслятор добавляет ещё одного зарубежного обработчика — Cloudflare (США).
- **Локализация (ч. 5 ст. 18 152-ФЗ).** Запись и хранение ПДн граждан РФ должны вестись в базах в РФ. Сайт заявки не хранит, поэтому единственное место их записи — Telegram за рубежом. Это аргумент за российский основной канал: почту или MAX.
- **Согласие.** С 01.09.2025 согласие на обработку ПДн оформляется отдельно от других документов (ч. 1 ст. 9 в ред. 156-ФЗ). Подписи «Нажимая кнопку, вы соглашаетесь…» может быть недостаточно. Скорее всего понадобятся чекбокс и страница политики обработки ПДн (ст. 18.1). Если чекбокс появится, поле `consent` добавляется в `parseLead` обратно совместимо (раздел 2).
- **Чат как хранилище ПДн.** Ограничить круг участников, убирать уволенных, включить автоудаление сообщений.

# Нумерация заявок

Заголовок сообщения содержит `#ДД-ММ-N`: общий счётчик обеих форм за день
по `Asia/Novosibirsk`. UUID клиента остаётся внутренним ключом дедупликации.
Номер резервируется перед отправкой и не используется повторно, поэтому при
ошибке доставки возможен пропуск. Успешный повтор в пределах дедупликации
не расходует номер. Это не постоянная очередь доставки.

`LEAD_NUMBER_DIR` задаёт постоянную директорию счётчика (локально `.lead-data`).
В Docker обязательно монтировать её с VPS, например
`-e LEAD_NUMBER_DIR=/app/lead-data -v "$PWD/lead-data:/app/lead-data"`.
Внутри — только пустые каталоги `ГГГГ-ММ-ДД/N`, без персональных данных.
Не удалять их при обновлении: они предотвращают повторную выдачу номеров.
При недоступном хранилище форма возвращает ошибку, сообщение не отправляется.
